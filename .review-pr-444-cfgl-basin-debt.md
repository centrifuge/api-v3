#### 3. Swap handler is doing fee math we usually push down

**File:** `src/handlers/basinHandlers.ts`  
**Lines:** 74–141

**GitHub comment:**

Handlers should mostly decode and delegate. This block loads state, calls `getSwapQuote`, picks fee bps by direction, computes `fee = grossOut - amountOut`, and bumps cumulative counters — same neighbourhood as `basinQuote.ts`.

I'd pull it into `BasinFeeService.computeSwapFee(...)` or a small helper next to `basinQuote`, so `Swap` reads like `RedeemInitiated`: load, call service, done. Easier to test quote failures and gross < net too.

**Example:**

```
COLLATERAL→CREDIT swap:
  Today: handler does Promise.all + fee math + insert + addCollectedFee
  RedeemInitiated neighbour: getSwapQuote → insert → debt.load → adjust pending → save
```

#### 4. `claimTransferRepayment` needs `_sort` on its `query` (service usage is fine)

**File:** `src/services/BasinDebtService.ts`  
**Lines:** 198–210  
**Also:** `src/services/EscrowService.ts` ~47–55, `src/services/AssetService.ts` ~108–120

**GitHub comment:**

Using `query` here in `BasinDebtService` is the right layer — no issue with that. What's missing is ordering: we filter and take `[0]` without `_sort`, so which row wins is DB-dependent.

Don't switch to `Service.get` either — that's `.limit(1)` with no `orderBy`, same problem `EscrowService.getLatest` was written to fix.

Neighbour pattern is still `query` in the service, with `_sort` and take `[0]` — see `getLatest` and `AssetService.getByToken`. For claims, the transfer has to come before the basin log in the tx:

```ts
const [claimed] = await BasinDebtChangeService.query(context, {
  // …existing filters…
  logIndex_lt: event.log.logIndex,
  _sort: [{ field: "logIndex", direction: "desc" }],
});
```

Optional helper name like `getClaimableTransferRepayment` is fine; main fix is the sort + `logIndex_lt`. If rows still tie, a `serviceWarn` like `getByToken` works.

**Example:**

```
Same tx:
  logIndex 10 & 12: TRANSFER_REPAYMENT, principalDelta=-50e18
  logIndex 15: RedeemCompleted

Today: query in service ✓, but no _sort → [0] depends on DB order
Fix: same query + logIndex_lt + _sort desc → [0] is logIndex 12
```

**File:** `src/helpers/bigintMath.ts`  
**Lines:** 39–67  
**Also:** `src/services/BasinDebtService.ts` ~54–62, `src/config/sky.ts` ~25–33

**GitHub comment:**

We've got parity tests for handlers, decimals, crosschain SQL, etc., but nothing on `rpow` / `scaleDecimals` / `projectDebt`. `rpow` is supposed to match Sky's round-half-up — worth a small unit file with known vectors (from `2da5906` or Maker fixtures).

**Example:**

```

Test locks projectDebt to hand-computed rpow
Someone tweaks rounding → test catches KPI drift before prod
```
